Security

The stack behind every product — and what isn't claimed.

I build software the way an attacker would try to break it. Every product goes through the same treatment: hardened auth, rate-limited endpoints, real authorization checks, and audit trails.

Authentication

  • httpOnly cookies — tokens never readable by JavaScript, so XSS cannot steal them
  • JWT with refresh token rotation — every refresh invalidates the previous token; stolen tokens die after one use
  • Token blacklist — revoked sessions stay revoked, forever
  • SameSite=Strict cookies — CSRF attacks blocked at the browser level
  • 2FA (TOTP) — built-in, works with Google Authenticator, Authy, 1Password

Rate Limiting & Brute-Force Protection

  • 30–44 rate-limited endpoints per product — login, 2FA setup, password reset, registration, and sensitive actions
  • django-axes — locks out attackers by both IP and username after repeated failures
  • Layered limits — IP + user-based defense prevents distributed attacks

Authorization

  • Ownership checks on every request — users can only touch their own resources
  • Role-based access control — user / staff / admin / org-owner
  • Multi-tenant isolation — organization data strictly scoped

Data & Transport

  • HSTS — forces HTTPS in production, browser remembers for 1 year
  • Secure cookies — only transmitted over HTTPS in production
  • Strong password validator — custom rules, 8+ chars, complexity checks
  • CSRF protection — Django's built-in system, hardened
  • XSS filter + nosniff — security headers on every response
  • CORS locked — restricted to explicitly allowed origins in production

Audit & Observability

  • Audit log — every sensitive action recorded (logins, password changes, 2FA, admin actions)
  • Session expiry handling — expired sessions auto-logout on both frontend and backend
  • Refresh event tracking — frontend knows when tokens are refreshed or rejected

Code Quality

  • 0 TypeScript errors — every product compiles clean under strict mode
  • 0 Django check issues — no deprecation warnings, no misconfigured models
  • No debug code — no console.log, no print(), no window.confirm() in shipped code
  • No marketplace leaks — clean license, no third-party branding, no leaked credentials

What This Means for Buyers

  • A codebase reviewed as though an attacker was going to try it
  • Security defaults that are safe out of the box — no configuration needed to be protected
  • A stack that matches what you'd build if you had a security team
  • Documentation that tells you exactly which settings to flip in production

What I Do NOT Claim

  • That any software is "unhackable" — no software is
  • That I have a third-party audit certificate — I don't, and neither do most sellers on any marketplace
  • That I can protect you from infrastructure misconfigurations on your own server
  • That I take responsibility for third-party dependencies (Stripe, Cloudflare, etc.)

What I do claim: the code is built and shipped with security as a first-class concern, not an afterthought.
